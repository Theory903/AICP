- OpenClaw’s most reusable pattern for AICP was manifest-first discovery with lazy runtime loading: load `plugin.json` metadata eagerly, import plugin code only on `load/enable`.
- AICP plugin manifests now need explicit `plugin_type`, typed lifecycle hooks, declared capabilities, dependency records, config schema, and permissions so registry/setup logic works before runtime execution.
- Hook registration is simplest when normalized around a small enum (`pre/post capability`, `pre/post workflow`, `startup/shutdown`) plus ordered async emission with per-plugin unregister support.
- Registry state tracking is clearer when lifecycle states are explicit (`discovered`, `loaded`, `enabled`, `disabled`, `unloaded`) and version/path/bundled metadata live on a single record object.
- Default sandbox policy should fail open only when no permission allowlist is configured; once configured, permission checks become an enforceable boundary for non-bundled plugins.
- AICP provider routing fit cleanly as a small core subsystem: Pydantic models for manifests/config, dataclasses for usage and aliases, a manifest registry for filtering + health checks, and a router that resets to primary after success and advances deterministically on failure.
- The channel package fit the existing core style by keeping normalization in Pydantic models, lifecycle behavior in small ABC-backed channel classes, and routing decisions in a registry/router pair with manifest priority plus allowlist checks.
- Built-in channels stayed testable without extra dependencies by letting console IO accept injected streams while webhook/api channels used in-memory queues for deterministic send/receive and health behavior.
- Cost/token tracking fit core conventions best as a tiny subpackage: dataclass models for usage/budget, stateless helpers for estimation/token counting, and a tracker that records immutable usage snapshots while enforcing budget thresholds after append.
- The webhook subsystem fits the core package cleanly as a small dataclass-driven subpackage: event/route models in `models.py`, dispatch and signature verification in `handlers.py`, and routing/registration kept in tiny focused classes for deterministic tests.
- Webhook signature verification is easiest to keep testable by separating timestamp expiry errors from digest mismatch; tests can then assert explicit failure modes while the FastAPI adapter converts signature exceptions into HTTP 401 responses.
